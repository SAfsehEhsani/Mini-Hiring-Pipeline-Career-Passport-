1. Executive Summary & Requirements Matrix

The Mini Hiring Pipeline empowers recruiters to manage candidate lifecycles across five sequential stages (Applied → Screening → Interview → Offer → Hired), enforcing strict progression invariants and an append-only cryptographic audit trail. An integrated single-box natural language search engine resolves complex recruiter questions without external dependencies or cloud latency.

3. Human-in-the-Loop: Disagreement with the AI

Where We Disagreed with the AI Assistant:

During initial system design, the AI assistant proposed integrating an external Cloud LLM API (such as OpenAI GPT-4o or Claude 3.5) to parse search box queries via serverless function calls, or alternatively using basic regular expression lookups.

The Human Architectural Decision & Rationale:

  • Sub-millisecond Recruiter Latency: External LLMs introduce 500ms–1500ms network roundtrips per keystroke, unpredictable rate limiting, and failure modes when working offline. A deterministic client-side tokenizer runs in < 2 milliseconds.
  • Candidate PII Privacy (GDPR/SOC2): Streaming recruiter queries containing candidate names, email addresses, and phone numbers to a third-party LLM introduces privacy compliance liabilities. Our hybrid parser executes entirely within the browser boundary.
  • Deterministic Explainability vs. Hallucination: Generative LLMs can hallucinate filters or inconsistently parse date thresholds (e.g. interpreting "since Monday" differently depending on temperature). The hybrid parser pairs exact calendar anchoring with Damerau-Levenshtein distance, ensuring 100% deterministic, explainable results.

4. The Intelligent Query Engine Architecture

The query engine evaluates candidate streams through a multi-stage deterministic pipeline:

  1. Tokenizer & Stopword Reducer: Normalizes contractions (who's, who has been, where is) and punctuation while preserving keyword stems.
  2. Damerau-Levenshtein Fuzzy Matcher: Computes string edit distance including adjacent character transpositions (e.g., "sharam" ↔ "Sharma" has edit distance 1), evaluating full names, first names, and last names.
  3. Relative Calendar Resolver: Dynamically anchors weekday strings (e.g. "since Monday") to the preceding calendar Monday relative to Date.now().
  4. Duration & Milestone Analyzer: Inspects candidate stage dwell times (e.g. "stuck in Screening for more than a week" → > 7 days) and historical audit log milestones ("reached Offer but didn't get hired").
  5. Scoring & Ranking Engine: Weighted relevance scoring ensures exact name matches (+100) and high fuzzy matches (+70) rank above general status matches, ordering results with best matches first.

5. What We Would Do With More Time

  • Multi-Requisition Pipelines: Support multiple concurrent job postings with customizable stage sequences (e.g., Sales vs. Engineering interview loops).
  • Distributed Event Sourcing (CQRS & WebSockets): Back the append-only log with a persistent distributed event store (Postgres WAL or Apache Kafka) with real-time multi-recruiter synchronization.
  • Cryptographic Merkle Tree Log Proofs: Hash-chain audit entries into a Merkle DAG so compliance officers can mathematically prove zero records were backdated or modified.
  • Automated SLA Notifications: Trigger automated webhooks, Slack alerts, or email reminders when candidates approach maximum stage dwell thresholds.
